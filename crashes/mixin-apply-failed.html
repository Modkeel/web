Minecraft crash: Mixin apply failed

A mod tried to change Minecraft's code and the code it expected was not there. Almost always the mod is for another Minecraft version, or two mods change the same code.

Updated October 2, 2026. Fabric, NeoForge and Forge.

What you see

The game closes while loading or right when a world opens. The crash report or log has one of these:

org.spongepowered.asm.mixin.transformer.throwables.MixinTransformerError: An unexpected critical error was encountered
Mixin [examplemod.mixins.json:LevelRendererMixin] from mod examplemod failed injection check
org.spongepowered.asm.mixin.injection.throwables.InvalidInjectionException: Critical injection failure
Mixin apply for mod examplemod failed examplemod.mixins.json:LevelRendererMixin

Why it happens

Mods change the game with mixins: small patches that say "add this code inside that method of Minecraft". A mixin names the exact method it patches. When the method is missing or different, the mixin cannot apply and the game stops on purpose, before it runs broken.

  • Wrong Minecraft version. The most common cause. A mod for 1.21.1 is not a mod for 1.21.10: Minecraft renames and moves code even between patch versions.
  • Two mods patch the same code. One mod already replaced the method the other one wanted to patch. Each mod works alone; together they crash.
  • Wrong loader or library version. A mod that patches another mod (for example Sodium or Fabric API) needs the version of it that it was made for.

Find the mod

  1. Open the newest file in crash-reports in your game folder, or logs/latest.log if there is none.
  2. Search for mixins.json. The line names a config such as examplemod.mixins.json and often from mod examplemod: that is the mod whose patch failed.
  3. If the error names a method of another mod, that other mod is the second half of a clash: the two do not work together in these versions.

Fix it

  1. Download the named mod again, picking your exact Minecraft version and loader on its Modrinth or CurseForge page.
  2. If it was already the right version, think of what you added last. Remove that mod and start again; if the game starts, the two mods clash.
  3. If there is no version of the mod for your Minecraft yet, remove it until there is. Keep a copy of your world first: removing a mod can remove its blocks and items.

Let the game tell you

The Modkeel Companion reads the crash on the next start, names the mod that most likely caused it and how sure it is, and offers to turn that mod off or go back to the mods that last worked. It backs up your worlds when your mods change. Free and open source, for Fabric, NeoForge and Forge.
